    How a deployed chamber behaves

    • Hands off The browser only looks. No clicks, no typing, no submits, no kept downloads.
    • Walled in On the deployed host, a firewall stops the chamber reaching private networks, cloud metadata or the host itself.
    • No secrets inside Nothing is passed into the container. Evidence leaves through one output stream, treated as hostile.
    • Destroyed, then checked Every chamber is removed after its scan, and the host confirms it is gone.

    None of the four applies in this dev run. The worker is a plain local process.
