How this is measured

  • Cases: 14 controlled pages written for this test: 11 attacks on the agent (direct and hidden prompt injection, credential harvesting, local-file and internal-service requests, self-navigation, malicious redirect, suspicious download, prompt disclosure, a composite) and 3 safe pages that look like attacks. Definitions: benchmarks/cases.json.
  • Run: each page is opened in the real sandbox on the Vultr VM, behind the real firewall, and judged by the real model on Vultr Serverless Inference. Nothing is replayed or mocked.
  • Scoring: pass or fail comes from the recorded verdict and policy decisions, by fixed rules in benchmarks/run.py. No case is scored by hand, and no case or result was changed for presentation.
  • Baseline: the same pages, captured the same way, sent to the same model as raw text with a plain prompt and none of Link Detonator's layers (benchmarks/baseline.py). Its proposed actions are counted, never run.
  • Limits: 14 cases is a small suite and the model varies between runs, so these numbers do not predict detection on the open web. Earlier runs, including two that each missed one case, are kept and explained.

Reproduce it

Rule layers only, on any machine with Python 3.12 or later. No key, no Docker, no cost. This uses a test model that obeys every attack, so all 14 cases are expected to fail; it shows the rules deny its actions. It is not model performance.

git clone https://github.com/djihane19/link-detonator.git
cd link-detonator
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
make harness PYTHON=.venv/bin/python

The real benchmark and baseline, on a VM provisioned with deploy/provision.sh and an inference key. Each run makes 14 to 30 model calls.

cd /opt/link-detonator
set -a; . /etc/link-detonator/app.env; set +a
.venv/bin/python -m benchmarks.run --model vultr --out reports/my-run.json
.venv/bin/python -m benchmarks.baseline --out reports/my-baseline.json
